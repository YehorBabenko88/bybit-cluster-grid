# Mission 3 deployment source extension

Physical deployment, office services, LS5/PC4/ADMINIT, real databases and physical automatic updates are forbidden. All installer entrypoints default to Prepare. Execution is constrained to an explicitly authorized ephemeral hosted Windows runner, or Python filesystem/driver tests in a `mission3-*` temporary cloud-lab directory. No release publication or physical activation was performed.

`unified_system.release_manifest` owns canonical `unified.release.v3`: exact six source commit/tree/version/API/artifact descriptors, dependency version closure, bounded ZIP sizes and producer workflow pins. Those workflow pins are provenance claims, not trust. The independently supplied publisher certificate SHA256 and detached SHA256 CMS signature are required before staging. The manifest cannot choose launch commands or service identities. `Build-UnifiedRelease.ps1` verifies supplied artifact pins and signs canonical bytes using a separately provisioned publisher key; it does not fetch or publish GitHub releases. `PowerShellCMSVerifier` reuses `SecurityPackage.psm1` with externally pinned helper/runtime bytes; no execution-policy bypass or learned publisher baseline.

`DeploymentAgent` is a local actuator. Enrollment and permits require the existing Grid server's authenticated authority, not client-selected roles. Its default execution scope denies mutation. A local lock covers immutable six-module staging, Grid current/previous/pending markers, release-aware activation and rollback. Verified detached signatures and exact signed capsule ZIPs are retained; a separate trusted journal records release/signature/Git-config digests. Rollback and idempotent activation reverify the external CMS pin, original artifact/bundle bytes, exact Git HEAD/tree and all source files against a fresh offline reconstruction. A tampered recovery release is stopped/blocked, never started. `stop()` persists administrative intent before touching the runtime; rollback does not clear it. Uninstall stops and preserves history, releases and recovery artifacts. Interrupted activation/failed rollback remains blocked for explicit recovery. Each signed module ZIP contains exactly `source.bundle`. The agent requires an externally pinned Git binary, clones offline without hardlinks/alternates/global/system config/replacement refs/hooks, checks exact commit/tree, and writes raw blobs plus Git index so existing Terminan/Strattester source guards still see a clean real Git checkout. ZIP traversal, Windows aliases, duplicate paths and links are rejected. This is a trusted single-writer local namespace model, not hostile administrator attestation.

Runtime bridge methods are `start_release(manifest, release_root)`, `stop_release()` and `health_release(release_id)`. Health must equal `{release_id,release_sha256,ready:true,modules:{six exact IDs:{version,ready:true}}}` after actual functional probes. HTTP200/PID liveness is insufficient. The parent runtime owns executable maps and dependency ordering.

The protocol3 rollout extension uses **existing** Grid `agent_releases`, `rollout_state`, and `rollout_nodes`. It does not elect a leader or maintain another distributed journal. The agent revalidates its current authenticated Grid permit after staging and at stop/pointer/start/healthy-commit boundaries. Namespace checks reject linked child directories, files, markers and locks before effects. One queued/verifying node fleet-wide is permitted: canary first, then serial rolling nodes. Registration is immutable; generations increase; failed health, timeout, stopped intent and stale ACKs cannot advance rollout. Claim/ACK require the consensus agent's `floating_leader_guard(leader)` and a locked live PostgreSQL service lease matching owner/epoch. DCSsession and PGepoch are rechecked independently; this is not an atomic transaction across Consul and PostgreSQL. The coordinator must enqueue only these returned permits through existing authenticated Grid commands, and keep legacy wave launcher away from protocol3 rows. Metadata-based guards now explicitly reject protocol3 in every legacy begin/launch/heartbeat entrypoint and exclude protocol3 expiry; these guards work without the new protocol column on legacy schemas.

`mission3-service.ps1` can install only the fixed stopped `Mission3LabUnified` service in the disposable runner namespace using externally pinned Python/NSSM/local launcher. It uses LocalService, demand start and no NSSM restart-on-clean-exit; the existing Grid supervisor owns bounded crash recovery and administrative stop semantics. Its safe uninstall requires persisted STOP plus a matching installation ownership receipt and actual SCM/NSSM executable, account, launcher parameters and root configuration; a caller-created second root cannot remove the first root’s service. It never deletes data. `mission3-install.ps1` verifies signed release and module closure and prepares the package; enrollment and start remain separately authenticated Grid operations.

Remaining integration work: parent runtime/coordination wiring, role-specific verified runtime/dependency provisioning including the official Hashicorp Consul artifact policy, actual GitHub immutable artifact transport acceptance (bounded exact-tag transport is implemented but not exercised against published releases), Windows PS5.1/7 execution evidence, actual NSSM acceptance and interrupted activation recovery drill. No physical readiness claim follows from portable source tests. The release candidate is **PARTIALLY_READY**, not a production deployer yet.
