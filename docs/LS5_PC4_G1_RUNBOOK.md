## STOP, recovery and removal

Designate an independent STOP authority before creation. STOP rejects new work and
revokes only test capabilities; drain/cancel via held handles, wait bounded, record
uncertainty and retain resources. If controller crashes, do not discover ownership
from object names, PID files, port or .env. Recovery reopens the protected durable
journal, validates volume/file/process/cluster identity and generations, then resumes
only approved cleanup after independent review. Unknown state remains blocked.

Rollback of this foreground test is controlled shutdown + preserved evidence/data.
It is NOT rollback-release.ps1 against the installed cluster. No old release activated,
no schema downgrade, no broad icacls/reset, no account disabling/deletion, no existing
DB/role/service/task removal. The default removal procedure is RETAIN. Never recursively
remove a path just because it contains the run ID. Native handle-based removal and
cluster-bound idempotent SQL cleanup require separate proof and approval.
