# Public trade admission and WAL refusal recovery

This is a correction to the existing `Worker.trade_stream`, not another feed engine or scheduler. It uses the existing FootprintBuilder, TradeContinuity, Storage.save and SegmentWAL durability contract. All verification uses synthetic local socket fixtures; live/physical acceptance is NOT_RUN.

Each socket subscribes to its exact `publicTrade.SYMBOL`. A matching successful subscription ACK is required. Valid early trade batches are held in arrival order until ACK, bounded to2000 frames and4MiB raw input in total; individual WebSocket/JSON frames are limited to1MiB and trade batches to1024 entries. An ACK failure or buffer overflow discards that unconfirmed socket epoch, reconnects with bounded backoff and degrades the next accepted observations rather than asserting GOOD.

`public_trade_validation.py` validates the entire batch before continuity, footprint or tape mutation: exact topic, optional per-trade symbol match, positive exact integer timestamp with a five-minute future guard, finite positive price/quantity, Buy/Sell side and bounded nonempty trade ID. Booleans, fractional timestamps, nonfinite JSON, unknown sides and malformed entries are rejected. A valid prefix of an invalid batch is not applied. Rejecting a batch is not durable raw-data quarantine; it is a fail-closed live admission decision. Subsequent observations are marked DEGRADED when rejected input may have affected the open interval.

Before any batch mutation, arithmetic preflight uses the actual finite positive tick size and current footprint state. Price/tick division, rounded price and per-level/per-minute/whole-batch volume must remain finite. It imposes no invented maximum market price. When tape capture is enabled, the actual existing MicroTapeAggregator kernel runs on only the current symbol’s fixed ten-field primitive state and scalar CVD. Its closed output and a prospective flush must remain finite before any real mutation; this catches CVD overflow across different minutes without another CVD formula or silent clamp. Unknown/oversized state is rejected before copying, and other symbols are never copied or modified. Invalid prefixes do not mutate buckets or seen IDs. Pending quality downgrades survive zero-accepted replays and pressure-driven collector replacement until an accepted aggregate actually carries them.

The Worker owns finalized rows outside cancellable collector tasks. A global1024-slot budget includes pending rows and worst-case finalization reservations across symbols. Reservation precedes aggregate mutation and remains held across micro-event awaits; a fixed finalization timestamp prevents extra unreserved minutes from closing during that await. Per-symbol drain locks and awaited collector cancellation prevent replacement streams from racing the same deque. Reassignment/resumption drains retained finalized rows before subscribing or reading new data.

`Storage.save_retained` registers one bounded, immutable logical-row admission keyed by its canonical digest. One retained task holds the existing enqueue lock across SegmentWAL.append and queue.put. A caller's20s deadline or cancellation does not cancel that handoff or invent another WAL ID. Retries join the same task and completed receipt; only the logical producer's explicit acknowledgement after observing completion releases it. The admission map is capped at1024 before task creation or append. Generic Storage.save remains compatible and cannot evict another retained producer's receipt. Unexpected post-append queue failure blocks new IDs until shutdown/replay rather than allowing an ordered ACK hole.

Storage success still means local fsynced WAL plus ordered queue admission, not CONTROL acceptance or database ACK. Existing queue workers, authentication, idempotent database persistence and ordered WAL acknowledgements remain authoritative. The Worker gives retained rows a bounded shutdown flush; Storage then quiesces new admissions and drains/cancels owned handoffs before closing its queue. An unqueued but durable WAL record is recovered in order on the next start before live producers are enabled. Python coroutine deadlines do not qualify OS/filesystem fsync latency. No new database credentials, ingestion API, automatic statistics repair or scientific authority is added.

Its old control-runtime/floating-leader changes must not be merged over the current Consul authority.

Raw pre-aggregation crash capture remains **BLOCKED / NOT_COMPOSED**. In-memory open buckets and unconfirmed pre-ACK frames can still be lost on process death or collector cancellation; finalized Worker-owned rows survive collector cancellation/reassignment, but remain vulnerable to process death until admitted to WAL. A bounded shutdown flush can remain incomplete while disk capacity is unavailable. These fixes do not prove lossless acquisition, exact reconstruction or repair of already published statistics. Separately integrate and qualify the existing source-owner quarantine protocol before claiming durable raw source capture. Historical provenance continues to state that exchange completeness is unattested; no “COMPLETE” status or training/trading permission is fabricated.
